# 考试报名信息采集与审核管理系统 · 使用说明

> 版本 v1.1.0 ｜ Windows 单文件 exe ｜ 数据存于本机 `data\`，**默认开放局域网访问**（可在系统维护关闭）

> 📖 **本文档已内置进程序**：双击 exe 启动后，左侧菜单点「使用说明」可直接在本系统内查看本文档，
> 顶部支持关键词查找（命中黄色高亮、自动滚动到首个）。无需翻找 `使用说明.md` 文件。

---

## 一、启动系统

1. 把 `考试报名系统.exe` 放到任意目录（建议单独建一个文件夹，例如 `D:\考试报名系统\`）。
2. **双击 `考试报名系统.exe`**。
3. 程序会自动：
   - 在 exe 同级创建 `data\` 目录（数据库、导出文件）；
   - 启动本地服务（默认 `http://127.0.0.1:8765`）；
   - 自动打开系统默认浏览器进入登录页。
4. 关闭系统：在黑色命令行窗口按 **Ctrl + C**，或直接关闭该窗口。

> 若 8765 端口被占用，程序会自动顺延到 8766、8767…，请以窗口中显示的地址为准。
> 也可手动指定端口：在命令行执行 `考试报名系统.exe --port 9000`。

### 1.1 局域网访问（多台电脑共用一台服务器）

**默认已开启**：双击 exe 后即监听全部网卡，同一局域网（同一间机房 / 办公室网络）的
其它电脑可以直接用浏览器打开本系统，无需任何额外操作。

启动时窗口中会显示监听地址与所有可用的局域网网址，例如：

```
  访问地址 : http://127.0.0.1:8765
  监听地址 : 0.0.0.0:8765（全部网卡，局域网可访问）
      http://192.168.1.20:8765（首选）
      http://10.10.0.5:8765
  [!] 安全提醒 : 局域网内任何设备都可打开本系统，请确认已修改初始管理员密码；
                若同事无法访问，请在 Windows 防火墙放行本程序或 8765 端口。
```

同事在自己电脑的浏览器里打开标了**「首选」**的那个地址即可
（**不要用 `0.0.0.0`**——它是监听地址，不是访问地址，浏览器打不开）。

#### 在系统维护里开关

管理员登录 → 「系统维护 → 局域网访问」：

- **允许局域网访问**开关（**默认开启**）；关闭后只监听 `127.0.0.1`，其它电脑一律访问不到
- 页面会回显当前监听地址与所有可访问网址
- **修改并保存后，需关闭黑窗口、重新双击 exe 才生效**——监听地址在服务启动时就确定了，
  运行中无法切换。若开关已打开但本次仍是仅本机，页面会明确提示你重启

#### 启动参数（可选）

| 参数 | 作用 |
|---|---|
| 无参数 | 按系统维护里的开关决定（默认开启 → 监听 `0.0.0.0`） |
| `--lan` | 强制监听 `0.0.0.0`，优先于开关 |
| `--host 192.168.1.20` | 只监听指定网卡，仅该网段可访问 |
| `--host 127.0.0.1` | 强制仅本机，优先于开关 |
| `--port 9000` | 指定端口（默认 8765，占用自动顺延） |
| `--no-browser` | 启动后不自动打开浏览器（服务器常驻时建议加） |

> **防火墙**：Windows 首次监听局域网端口时通常会弹窗，请勾选「允许访问」。
> 若同事打不开，多半是被防火墙拦了——可用管理员身份执行：
> `netsh advfirewall firewall add rule name="考试报名系统" dir=in action=allow protocol=TCP localport=8765`
>
> **安全**：局域网模式会把系统暴露给同网段所有设备，请务必先修改初始管理员密码；
> 采集结束后可在系统维护里关掉开关。数据仍保存在本机 `data\` 目录，不会上云。

## 二、首次登录（正式版本不含任何测试数据）

首次启动时数据库为空，系统只自动创建一个管理员账号：

| 角色 | 账号 | 密码 |
|---|---|---|
| 管理员 | `admin` | `Admin@123` |

初始管理员未预设手机号与邮箱，登录后可在「个人中心」补充，便于后续找回密码。
出于安全考虑，**登录页不展示任何账号或密码提示**，初始密码以上表为准，请妥善保管本文档。

**请立即登录后到「个人中心 → 修改密码」改成自己的密码。**

其余账号一律由管理员在「用户与权限管理」中开通，或由考生在登录页自助注册。

> 如需在演示/培训环境预置演示数据，可设置环境变量 `EXAM_SEED_DEMO=1` 后启动，
> 会额外写入演示考试批次、演示报名数据与演示账号。

## 三、角色与权限（5 类账号）

系统采用「角色 → 权限组 → 数据范围」三层模型，**全部由后端强制核验**，前端仅按权限渲染菜单。

| 角色 | 可做的事 | 数据范围（默认） |
|---|---|---|
| **管理员** `admin` | 全部功能：批次管理、字典与考试类型、用户与权限、批量导入、审核、导出、分析、数据大屏、系统维护 | 全校 |
| **审核员** `reviewer` | 审核（通过 / 驳回 / 退回）、导出、分析、数据大屏、实名审核 | 全校 |
| **二级学院审核** `college_reviewer` | 审核、导出、分析、数据大屏、实名审核（无批量导入） | **本院系** |
| **班主任** `head_teacher` | 报名、批量导入、导出、分析、数据大屏（本班范围） | **本班级（可管理多个班级）** |
| **考生** `candidate` | 在线报名、证件照制作、实名认证、AI 助手 | 仅本人 |

权限组一览（可在「用户与权限管理 → 权限组核验」查看每个账号实际生效的权限；
编辑账号时每个开关下面都有一句话说明，不必猜它能做什么）：

| 功能组 | 说明 |
|---|---|
| 在线报名 `apply` | 填报与提交自己的报名信息，可撤回待审记录 |
| 信息审核 `audit` | 审核范围内的报名记录：通过 / 驳回 / 退回修改 |
| 批量导入 `import` | 批量导入报名数据与证件照（仍受本人数据范围约束） |
| 汇总导出 `export` | 汇总导出报名数据与照片（导出范围为可见范围） |
| 数据分析 `analysis` | 查看统计分析与数据看板下的明细报表 |
| 考试批次管理 `exam_manage` | 新建 / 编辑 / 发布考试批次，设置照片要求 |
| 字典与考试类型维护 `dict_manage` | 维护字典（学院、部门、职业、科目等）与考试类型字段 |
| 用户与权限管理 `user_manage` | 开通账号、改角色与权限（该页仅管理员角色可用） |
| 数据看板 `dashboard` | 查看 16:9 数据大屏 |
| 证件照制作 `idphoto` | 使用证件照制作（抠图、换底、排版） |
| 实名认证 `realname` | 填写并提交本人的实名认证信息 |
| 实名信息审核 `realname_audit` | 审核他人提交的实名信息（通过 / 驳回） |
| AI 助手 `ai` | 使用 AI 助手问答与智能填表建议 |
| 系统维护 `system_manage` | 系统维护：网关配置、数据清理、测试模式 |

- 范围类（四档，由小到大）：**本班级** → **本年级** → **本院系** → **全校**

数据范围四档说明：

| 档位 | 过滤依据 | 说明 |
|---|---|---|
| 本班级 `scope_class` | 账号的「管理班级」字段（多个用逗号分隔） | 班主任默认档位，按 `class_name IN (...)` 收敛 |
| 本年级 `scope_grade` | 账号的「年级」字段 | 报名表无年级列，按同年级班级关联 `users` 匹配 |
| 本院系 `scope_college` | 账号的「院系」字段 | 二级学院审核默认档位（计算机类比 `school`、普通话类比 `department`） |
| 全校 `scope_all` | 不过滤 | 管理员 / 审核员默认档位 |

> 管理权限级别 = 具备「批量导入」权限，即 管理员 / 班主任。
> 二级学院审核**不是**管理权限级别，不能批量导入，只能审核与查看本院系数据。

> **关于 `本年级`**：报名表本身没有年级列，这一档是按**考生账号上的年级字段**关联班级匹配的。
> 因此批量导入时请满足其一，年级才会落到考生账号上：
> ① 导入表里带「年级」列（系统会自动识别，也可在预览界面手工指定）；
> ② 表里没有该列时，在导入预览的「整批默认值」里补一个统一年级。
> 两条都没有、且导入时又关闭了「同时创建考生账号」的，这一档会漏掉他们——
> 这种情况请改用本院系 / 本班级。

### 3.1 单独授权：按功能开关逐个调整

除了角色自带的默认权限，管理员还可以对**某一个账号**单独开关功能：

1. 进入「用户与权限管理」，点某账号的 **编辑**；
2. 在 **功能权限（可逐个开关）** 区域，逐项拨动开关（14 个，每项都带一句话说明，
   并标注该账号角色是否默认开启）；
3. 保存即可生效（后端会强制核验，不只是隐藏菜单）。

说明：

- 未单独设置时，账号**沿用角色默认权限**；一旦调整，该账号即标记为「单独授权」，列表中会显示
  <u>单独授权</u> 标签，此后不再自动跟随角色变化。
- 需要恢复时点 **「恢复角色默认权限」**，保存后即清除单独授权、重新跟随角色。

### 3.2 单独设定数据范围（可收窄，不得放宽）

同一个功能，不同级别能看到的数据范围不同。除角色默认档位外，管理员还可以对**单个账号**
单独设定数据范围：

1. 进入「用户与权限管理」，点某账号的 **编辑**；
2. 在 **数据范围（可见哪些数据）** 区域选择档位；
3. 若选了「本年级 / 本班级」，需同时在下方 **范围依据字段** 填写年级 / 班级，否则该账号
   将看不到任何数据（权限组核验会标「待完善」）。

规则：

- 可选档位**只能等于或小于角色默认档位**。例如二级学院审核最高到「本院系」，
  不能设为「全校」；班主任最高到「本班级」；审核员 / 管理员四档都可选。
- 收窄立即生效，无需对方重新登录；列表里会显示 <u>单独设定</u> 标签。
- 选 **「跟随角色」** 并保存，即恢复为角色默认档位。
- 这样可以做到「同是审核功能，二级学院审核只看本院系、审核员看全校」。
- 管理员**不能修改自己的权限**（防止误关后无法恢复），需由其他管理员操作。
- **对方无需重新登录**：权限保存在服务端，被调整的账号在下次打开页面或切换菜单时
  即会拉取最新权限，菜单与按钮同步更新（已被关闭的页面会自动跳转回首页）。

## 四、注册与登录

### 4.1 考生自助注册

登录页 →「立即注册」。页面**只保留必填项**，且**只显示管理员已开启的验证方式**
（页面上有「只显示管理员已开启的方式」的说明）：

1. **图形验证码**（默认开启）：点击图片可刷新
2. **手机验证码**：填写手机号 → 点「获取验证码」→ 60 秒后可重发
3. **邮箱验证码**：填写邮箱 → 点「获取验证码」→ 60 秒后可重发

管理员在「系统维护 → 注册验证方式」里开关这三种方式（**至少保留一种**）；
没开启的方式在注册页**不会出现**，即便手工调用接口也会被拒绝，不会谎报「已发送」。
手机号只走短信、邮箱只走邮箱，两者互不相干。

> 未配置邮件 / 短信网关时，验证码走**演示模式**：验证码直接输出在 exe 的黑色控制台窗口，
> 页面也会提示「网关未配置」。配置方式见第十一节。
> 找回密码不受注册开关限制——否则管理员关掉短信后所有人都找不回密码。

密码规则：不少于 8 位，且包含字母 / 数字 / 符号中的至少两类。

### 4.2 登录

- 账号可以是**用户名或手机号**
- **记住我**（默认勾选）：
  - 勾选 → 令牌存本地，有效期 12 小时，关闭浏览器仍保持登录
  - 不勾选 → 令牌只存当前标签页，有效期 2 小时，关闭浏览器即失效
- 连续输错 5 次将锁定 5 分钟

### 4.3 找回密码

登录页 →「忘记密码」→ 填写注册时绑定的**手机号或邮箱** → 点「发送验证码」→
填入收到的验证码 → 设置新密码 →「确认重置」。

- 验证码走与注册相同的通道（邮件 / 短信；未配置网关时为演示模式，见第十一节）
- 若该手机号或邮箱**未绑定任何账号**，会明确提示「未找到」而不是静默失败
- 重置成功后即可用新密码登录，无需重启程序

> 这也是为什么建议考生**补全手机号与邮箱**：账号一旦遗忘密码，只能凭其中之一找回。

## 五、考试类型管理（管理员）

系统内置三套**基础模板**，管理员可基于模板新增自己的考试类型（如「英语四级考试」「普通话专项测试」）：

| 基础模板 | 采集字段 | 院系列 | 官方导出模板 |
| --- | --- | --- | --- |
| 计算机类考试 | 13 个（考试机构 / 报考科目字典） | school | 计算机类 |
| 普通话水平测试 | 20 个（职业字典 + 省市区三级联动） | department | 普通话 |
| **通用考试报名** | 8 个核心字段 + **自定义字段**（自由增删） | college | 通用汇总表 |

新增类型 = 选一个基础模板 + 起名称与编码，**不需要改任何程序**，
报名 → 导入 → 审核 → 导出 → 分析整条链路直接复用。

操作路径：**考试类型管理** →「新建考试类型」

1. **类型名称**：展示用，随时可改（列表、批次、导出文件名都用它）
2. **编码**：系统内部标识，小写字母开头、仅含小写字母 / 数字 / 下划线，长度 2-30，创建后不可改
3. **基础模板**：决定该类型采集哪些字段、数据存在哪张表、导出哪套官方模板，**创建后不可更改**
4. **采集字段**：可逐字段设置
   - **采集**：关闭后该字段不出现在报名表、导入模板与导出文件中
   - **必填**：可在模板默认必填之外追加必填项（系统必填项不可取消）
   - **显示名**：改名后同步生效于报名表单、导入模板表头、导出文件表头与审核详情
5. **启用 / 停用**：停用后新建批次时不再出现在类型下拉中；**已建批次不受影响**，可继续报名与审核
6. **删除限制**：内置类型不可删除；已被考试批次使用的类型不可删除（可先停用）

> 提示：报名表单会按类型配置自动渲染 —— 关闭的字段不显示、改名后的标签直接生效，
> 不需要逐个页面维护。

### 5.1 通用考试报名模板（支持自定义字段）

前两套模板的字段是官方固定的，只能「开关 / 改名 / 追加必填」。
如果这两套都不合适（比如要采集「报考等级」「是否住宿」「特长方向」这类官方模板没有的信息），
选**通用考试报名**作为底座，然后自由增删字段。

**固定核心字段（8 个，可关闭 / 改名，系统必填为姓名、性别、证件号、手机号）**

| 字段 | 说明 |
| --- | --- |
| 姓名 / 性别 / 证件类型 / 证件号码 | 身份信息，证件号带合法性校验 |
| 手机号码 / 电子邮箱 | 联系方式，手机号校验 11 位且第二位为 3-9 |
| 班级 / 院系 | 用于「本班级 / 本院系」数据范围过滤 |

**自定义字段**（路径：考试类型管理 → 编辑该类型 →「自定义字段」→「添加字段」）

| 配置项 | 说明 |
| --- | --- |
| 字段名称 | 展示用，如「报考等级」，≤ 30 字 |
| 字段标识 | 系统内部 key，小写字母开头，**创建后不可改**；不能与固定字段或保留字重名 |
| 类型 | 单行文本 / 多行文本 / 数字 / 日期 / 下拉单选 / 下拉多选 |
| 选项 | 下拉类必填，每行一个；多选在批量导入时用「、」分隔 |
| 提示语 | 输入框占位提示 |
| 必填 | 报名与导入时强制校验 |
| 排序 | 数字越小越靠前 |

- 单个类型最多 **30 个**自定义字段
- 自定义字段会**自动同步**到：报名表单、批量导入模板（含「可选值」页）、审核详情、导出文件表头
- **删除字段只影响展示与导出**，已提交的历史值仍保存在数据库中，不会丢
- 值保存在报名记录的扩展数据里，导出时多选自动用「、」连接

> 若已用前两套模板建过批次，它们不受影响；通用模板是新增的第三套，老数据无需迁移。

## 六、按角色操作指引

### 6.1 管理员

1. **考试批次管理** →「新建考试批次」（也可直接访问深链 `#/exams/new`）
   - 选择考试类型（内置两套模板 + 管理员自定义的考试类型，详见第五节）
   - 选择年份 + 月份 → 批次名称自动生成
   - 设置报名开始 / 截止时间
   - 选择「存为草稿」或「立即发布（报名中）」
   - 列表可对批次做 发布 / 截止 / 重新开放 / 归档 / 删除（仅草稿可删）
   - 报名窗口到期后系统每分钟自动检查并关闭批次

2. **用户与权限管理** →「开通账号」（**仅管理员可用**，其它角色看不到该菜单，
   管理员也无法通过「单独授权」把它开放出去）
   - 页面按角色分标签页：**全部 / 管理员 / 审核员 / 班主任 / 二级学院 / 学生**，
     标签上直接显示该类账号数量，点开即只看这一类；列表内容超出时在表格内滚动（表头吸顶）
   - 填写用户名、姓名、手机号、邮箱，选择角色（考生 / 班主任 / 二级学院审核 / 审核员 / 管理员）
   - 「院系」从「二级学院」字典下拉选择（也可直接输入新值）；
     「部门」从「部门」字典选择，可留空
   - 选择**班主任**时**必须填院系 + 至少一个所带班级（多个班级用英文逗号分隔）**
     （决定该账号能看到哪些数据；未填写将看不到任何报名数据）
   - 选择**二级学院审核**时**必须填院系**（该账号只能看到本院系的报名数据；
     无批量导入权限，只做本院系范围内的审核与查看）
   - 还可对单个账号**单独设定数据范围**（只能收窄、不能放宽），详见 3.2 节
   - 初始密码可自行设置，**留空则自动生成**，创建成功后弹窗展示，请及时告知本人
   - 列表可随时 编辑资料、调整角色、启停（开关）、重置密码、查看该账号的报名记录
   - 保护规则：不能禁用或修改自己的账号；系统至少保留一名启用的管理员
   - **权限组核验**（右上角按钮）：逐账号核对「角色 → 权限组 → 数据范围」是否自洽，
     标记「待完善」的账号请补全管理范围

3. **批量导入** → 见第七节

4. **汇总导出** → 选择批次 → 选择状态（默认仅已通过）→ 预览 → 导出 xlsx

5. **数据分析** → 按批次 / 类型 / 日期区间查看多维图表

6. **数据看板大屏** → 16:9 深色大屏，30 / 60 秒自动刷新，适合投屏；
   右上角「全屏展示」进入浏览器全屏（按 **ESC** 退出），进出全屏图表会自动重算尺寸

7. **字典维护** → 自助维护「考试机构 / 报考科目 / 从事职业 / 二级学院 / 部门」五类字典（见 6.6 节）
8. **系统维护** → 查看运行信息与数据规模；配置邮件 / 短信网关；正式交付前清理测试数据（见第十一、十三节）

### 6.2 班主任

1. **批量导入** → 批量导入所管理班级的报名数据
   - 导入行上的「班级」字段必须落在班主任的管理班级内，否则该行报错；未填班级时归入第一个管理班级
   - 导入数据被严格收敛在班主任的管理班级，**无法越界导入**
2. **报名信息审核** → 只能**查看**范围内报名数据与审核历史，不显示审核按钮
   （审核动作由审核员与管理员执行）
3. **汇总导出** → 只能导出范围内的数据
4. **数据分析** → 统计口径自动收敛到自己范围内

> 班主任支持同时管理多个班级：开通 / 编辑时在「管理班级」中填写多个班级（逗号分隔），
> 其列表、导出、分析均按 `班级 IN (管理班级列表)` 收敛。

### 6.3 二级学院审核

介于「班主任（本班）」与「审核员（全校）」之间的一级审核，负责本院系报名数据的审核把关。

1. **报名信息审核** → 只能看到**本院系**的报名数据（按账号上绑定的「院系」过滤）
2. 审核动作与审核员完全一致：通过 / 退回修改（必填原因）/ 驳回（必填原因），
   也支持勾选多条批量处理（单次上限 500 条）
3. **汇总导出 / 数据分析** → 统计与导出口径同样收敛到本院系
4. **无「批量导入」权限**（非管理权限级别），需要导入请联系管理员 / 班主任
5. 开通时若未绑定院系，「权限组核验」会标「待完善」——该账号将看不到任何数据

### 6.4 审核员

1. **报名信息审核** → 按批次 / 类型 / 状态 / 关键字筛选（也可用深链 `#/review/12` 直达某条记录）
2. 点击「详情」查看完整报名字段与历史审核记录
3. 三种审核动作：
   - **通过**：意见可不填
   - **退回修改**：必须填写原因，考生可修改后重新提交
   - **驳回**：必须填写原因
4. 勾选多条记录后可**批量**通过 / 退回 / 驳回（单次上限 500 条）
5. 无「批量导入」权限，如需导入请联系管理员 / 班主任
6. 默认可见全校；管理员可按需把某个审核员**收窄**到本院系 / 本年级 / 本班级（见 3.2 节）
7. **代考生撤回**：在待审核记录的详情里可点「代考生撤回报名」，用于考生本人联系不上、
   又需要撤销该条记录的场景（限报名期内，且只能撤回自己数据范围内的记录）

> 「撤回」与「驳回」不同：撤回是**删除该条记录**，驳回是**保留记录并标记不通过**。
> 需要留下审核痕迹时请用「驳回」。

### 6.5 考生

1. **首页** → 查看开放报名批次 → 「立即报名」
2. 按类型填写表单：
   - **计算机类考试（13 项）**：考试机构（下拉，选编码自动带出机构名称）、考点编码、姓名、性别、证件类型、证件号码、报考科目（下拉）、院校、班级、学历、手机号（11 位）、Email、通讯地址
   - **普通话水平测试（20 项）**：姓名、性别、民族、证件类型、证件编号、从事职业（下拉）、所在单位、联系电话、学号、班级、院系、联系地址、邮寄地址、邮编（6 位）、出生省/市/县区（三级联动）、现居住省/市/县区（三级联动）
3. 提交后状态为「待审核」，可在**我的报名**中查看进度
4. 状态为「待审核」或「已退回」时，报名窗口内可**修改**或**撤回**
5. 忘记密码时，可在登录页用「忘记密码」自助重置（见 4.3 节）

### 6.6 字典维护（管理员）

**入口**：左侧菜单「字典维护」（需考试管理权限）

字典是**报名校验、批量导入匹配、表单下拉**三处共用的数据源。系统预置了官方模板中的
考试机构、报考科目与从事职业，管理员可自助增删改：

| 字典 | 影响范围 |
|---|---|
| 考试机构 | 计算机类报名的「考试机构」下拉、机构编码校验、导入时的机构匹配 |
| 报考科目 | 计算机类报名的「报考科目」下拉、导入时的科目匹配 |
| 从事职业 | 普通话报名的「从事职业」下拉、导入时的职业匹配 |
| **二级学院** | 报名表「院系 / 考生院系」下拉、账号「所属院系」（决定本院系数据范围） |
| **部门** | 账号「所属部门」，用于区分管理员 / 审核员 / 班主任等教职工归属（纯标识，不影响数据范围） |

> **二级学院与部门的区别**：二级学院对应教学单位（如「信息工程学院」），会作为院系范围过滤的依据；
> 部门对应行政 / 岗位归属（如「教务处」），只用于标识与查询。两类都可以先建字典再在账号里选择，
> 也可以直接输入新值（下拉支持自由输入）。

**出厂不预置任何字典值** —— 首次启动时二级学院 / 部门都是空的，请按本单位情况录入。

> 早期版本内置过一套示例学院与部门，已全部移除：程序会随成品对外分发，
> 内置什么就等于把使用单位的组织架构公开出去。录入后不会被重启覆盖，可放心改。

- 二级学院：教学单位（如「信息工程学院」），院系范围过滤的依据
- 部门：行政 / 岗位归属（如「教务处」），只用于标识与查询
- 院内岗位：常见的有**学工办（辅导员）**、**专职教师**，归属到某学院后即表达「XX 学院 - 学工办」

> **层级是平铺的，不是树**：部门只是「可以归属到某个学院」（字典项上多一个所属学院字段），
> 不做嵌套上下级。学工办（辅导员）与专职教师作为部门候选值，
> 归属到某个学院后即可表达「XX 学院 - 学工办」。

**给部门指定所属学院**：切到「部门」页签 → 列表里多一列**所属学院** → 点「编辑」→
在「所属学院」下拉里选学院（可清空）。

- 留空 = **校级部门**（教务处、学生处这类不属于任何学院），任何学院都能挂
- 院内岗位（学工办（辅导员）、专职教师）请选上所属学院
- 所属学院必须是「二级学院」字典里已有的值，填错会被拒绝
  （否则这个部门会永远挂不到任何学院下面，还查不出来）
- 效果：在**用户与权限管理 → 编辑账号**里选好院系后，部门下拉会自动筛出
  「该学院的部门 + 校级部门」，标签形如「学工办（辅导员）（信息工程学院）」；
  仍可直接手工输入其它部门

操作要点：

- 支持**关键字检索**、新增、改名、删除，改动**立即生效，无需重启**
- 列表会显示每条字典值的**「被引用」次数**（有多少条报名记录在用它）
- **被引用的条目不能删除**——避免历史报名数据失去参照。若确实想停用，
  建议改名为「xxx（停用）」而不是删除
- **改名不会改写历史报名记录**：已提交的记录仍保留原值，导出也以原值为准，
  仅在改名后的新导入与新报名中生效

> 省市区三级、证件类型、民族、学历来自官方模板，保持只读，不在此处维护。

## 七、批量导入（管理员 / 班主任）

**入口**：左侧菜单「批量导入」

1. **选择批次并准备文件**（两种方式任选）
   - **方式 A（推荐给首次使用）**：点「下载导入模板」→ 按模板填写
     - 模板 Sheet1 表头与官方模板完全一致，第 2 行是示例数据（**导入前请删除**）
     - 模板第 2 个 Sheet「可选值」列出可用的机构编码、报考科目、从事职业、省市区，
       以及本次导入的数据范围说明
   - **方式 B（推荐给已有名单的单位）**：**直接上传自己手里的表格**
     （花名册、教务系统导出等），无需改成模板格式 —— 见下方「智能识别」

2. **填写规则**
   - 表头**顺序可以调整**，也**允许多余列**（如序号、备注，不会被导入）
   - 系统会自动探测表头所在行（前 5 行内），首行是标题也能处理
   - 必需列：
     - 计算机类：姓名、证件号码、手机号码、报考科目（另有考试机构编码、考点编码必填，
       若表里没有可在导入界面填「统一默认值」）
     - 普通话：姓名、证件号码、联系电话、从事职业
   - 下拉类字段需从模板「可选值」中取值；写得不标准时系统会尝试自动纠正
     （如「大学本科」→「本科」、「汉」→「汉族」），纠正不了才会报错
   - **重要信息的合法性校验**（单条报名与批量导入同样生效，填错会给出明确提示）：
     - **身份证号**（证件类型为「居民身份证」时）：必须 18 位，且
       **省份代码**（前两位）、**出生日期**（第 7-14 位）、**末位校验位**均需合法，
       按国家标准 GB 11643 校验（末位可为数字或字母 X）
     - **手机号码**：11 位数字且第二位为 3-9（如 13812345678）
     - **邮政编码**：6 位数字；**Email** 按常规格式校验
     - 证件类型为 **香港 / 澳门 / 台湾** 时，按 6-20 位字母或数字校验

3. **智能识别：任意表头也能导**（方式 B）
   选择文件后系统会先解析并展示**列匹配结果**，确认无误再导入：

   - 逐列显示「文件中的列 → 识别为哪个字段」，并标注可信度：
     **精确**（完全匹配）/ **较可能**（相近写法）/ **推测**（关键词命中）/ **未识别**
   - 识别错了可在下拉框里**手工改判**；不需要的列选「不导入」
   - 未识别的列（如序号、备注）不会导入，会在顶部提示
   - 常用别名举例（无需照抄，系统按名称智能匹配）：

     | 你要导的列 | 能识别的写法 |
     |---|---|
     | 姓名 | 姓名、学生姓名、考生姓名、姓名（必填） |
     | 证件号码 | 证件号码、身份证号、公民身份号码、证件编号 |
     | 手机号码 | 手机号码、联系电话、电话、手机、联系方式 |
     | 班级 | 班级、所在班级、专业班级、行政班级 |
     | 院校 / 院系 | 学校、院校、学院、所在院系、就读院校 |
     | 学历 | 学历、文化程度、教育程度 |
     | 出生 / 居住地 | 出生地省、籍贯省、现居住地市、现居区县 等 |

   - **数据自动转换**（无需手工整理）：

     | 字段 | 转换示例 |
     |---|---|
     | 性别 | `M` / `男性` / `1` → `男`；`F` / `女性` / `2` → `女` |
     | 证件类型 | `身份证` → `1`、`香港居民身份证` → `6` |
     | 手机号 | `138 0013 8000`、`+86 138-0013-8000`、Excel 科学计数法 → `13800138000` |
     | 证件号码 | 去除空格与横线，末位 `x` → `X` |
     | 省 / 市 / 县区 | `江苏`、`江苏省` → `江苏省`（按省→市→县级联校正） |
     | 学历 / 民族 / 科目 / 职业 | 与字典模糊匹配并纠正 |

4. **上传并导入**
   - 确认列匹配无误后点「按当前匹配导入」
   - 导入后的审核状态可选「直接标记为已通过」或「标记为待审核」
   - 可勾选「同时创建考生账号」：系统按证件号自动建号，
     用户名 = 证件号后 8 位（冲突时自动加后缀），初始密码 = 证件号后 6 位（不足则补足 8 位）
   - 逐行校验，返回成功 / 失败明细；点「下载失败明细」可得失败报告 xlsx

5. **导入记录**
   - 右侧列表保留最近 20 次导入批次，可随时重新下载失败明细
   - 班主任只能看到自己发起的导入批次

**校验规则**（任一条不通过该行即失败，不影响其他行）：

- 证件号码格式、文件内证件号重复、本批次已存在同证件号记录
- 手机号 11 位、Email 格式、邮编 6 位
- 机构编码 / 报考科目 / 从事职业必须在字典内
- 出生地、现居住地三级联动必须匹配（省 → 市 → 县区）
- 管理范围自动归入导入人所属班级 / 院系

## 八、证件照管理

### 8.1 个人上传

考生本人或管理员在 **个人中心 → 证件照** 上传：

- 支持 JPG / PNG，单张不超过 5 MB
- 一个账号只保留一张，再次上传自动覆盖
- 照片用于报名提交与审核时的身份核对

### 8.2 批量导入（管理员）

进入 **用户与权限管理 → 批量导入证件照**，一次选择多张照片，
系统会先给出匹配结果，确认无误后再覆盖。

**命名规则**：把照片文件名改成能标识考生的信息（不含扩展名），例如：

| 文件名示例 | 匹配依据 |
| --- | --- |
| `320102199501011239.jpg` | 证件号码 |
| `20210001.jpg` | 用户名 / 学号 |
| `13900000000.jpg` | 手机号 |
| `张三.jpg` | 姓名 |

**匹配优先级**：证件号码 → 用户名/学号 → 手机号 → 姓名，命中即止。

**重名不猜**：若按姓名匹配到多个账号（例如两个「张三」），该照片**不会覆盖任何人**，
结果里标为「重名跳过」——请把文件名改成证件号或学号后重新上传。

导入结果会列出：将覆盖多少张、重名跳过、未匹配、重复与无效文件；
未采用的文件名集中列出，便于修正后重传。

> 提示：批量导入报名数据时若勾选「同时创建考生账号」，系统会自动把证件号码写入新账号，
> 因此导入生的照片可以直接按证件号命名匹配。

### 8.3 一键导出（管理员）

进入 **汇总导出 → 证件照一键导出**，选择考试批次、审核状态（可选）、班级（可选）与格式后
点「一键导出」，系统会把照片按目录打包成一个 zip 下载。

> 单次最多导出 5000 条。人数较多时可用「班级」下拉分批导出；
> 班级列表按当前账号的数据范围生成，二级学院审核员只会看到本院系的班级。

**目录结构**（逐级建目录，解压即可用）：

```
计算机类考试-2026年9月/
├─ 计算机学院/
│  ├─ 计算机2101/
```

### 8.4 证件照尺寸与底色（考试照片要求）

**个人中心上传的是原始照片本身，系统不再改动它**。需要几寸、什么底色，
由管理员在考试批次上声明，或由考生自己在「证件照制作」里做好后保存回来。

管理员在 **考试批次管理 → 新建/编辑 → 照片要求** 里可设置：

| 选项 | 取值 | 说明 |
|---|---|---|
| 尺寸 | 不限制 / 一寸（295×413）/ 二寸（413×579）/ 保持原图尺寸 | 留空 = 不限制 |
| 底色 | 不限制 / 白底 / 蓝底 / 红底 / 透明底（PNG） | 留空 = 不限制 |

批次列表的「照片要求」列会直接显示（如「一寸照片 · 白底」，不限制时显示「不限制」）。

- **个人中心 → 证件照**：单张直传，**不做任何抠图/换底**，原样保存
- 需要特定规格时：进「证件照制作」→ 点 **「调用我的照片」**（直接把个人中心的照片取进编辑器）
  → 选好尺寸底色生成 → 点 **「保存到个人中心」**
- **用户与权限管理 → 批量导入证件照**：整批统一处理，弹窗里同样可选规格

> 抠图模型内置在软件里，**全程离线**，不需要联网、不上传任何照片。
> 这样职责很清楚：上传页不知道规格，制作页不负责存储。

### 8.5 证件照制作（独立功能栏）

左侧菜单 **「证件照制作」** 是一个独立工具：不针对任何考生、不写库，
上传 → 生成 → 下载，用完即走。适合帮学生临时处理一张照片，
或在批量导入前先试好尺寸底色。

| 步骤 | 说明 |
|---|---|
| 1. 选照片 | 支持 JPG / PNG，单张上限 20MB、边长上限 6000；也可点 **「调用我的照片」** 直接取用个人中心已上传的照片 |
| 2. 看抠图效果 | 页面自动先做一次抠图预览，背景没抠干净就换一张背景更干净的照片 |
| 3. 调参数（可选） | 展开「调整参数」面板按需微调，见下表 |
| 4. 选尺寸 | 一寸 295×413 / 二寸 413×579 / 保持原图尺寸 |
| 5. 选底色 | 白底 / 蓝底 / 红底 / 透明底（PNG）/ **不换底** |
| 6. 生成并下载 / 保存 | 直接下载成品，或点 **「保存到个人中心」** 覆盖本人证件照 |

**可调参数**（解决「换底后边缘/底部漏出原背景色」）：

| 参数 | 范围 | 作用 |
|---|---|---|
| 抠图阈值 | 0–255（默认 55） | 低于该透明度的像素直接丢掉。原背景**残留色边**时调大 |
| 边缘羽化 | 0–60（默认 10） | 阈值到「阈值+羽化」之间的过渡带。头发丝**边缘发硬**时调大 |
| 底部补底 | 0–60（默认 12） | 底部这个高度比例内，非纯主体一律压成全透明。**底部漏色**时调大 |
| 留白填充 | 边缘色（默认）/ 白色 | **仅「不换底」时生效**：等比排版留下的白边填什么颜色。换底色时留白一律用所选底色（整幅才均匀） |

- 「不换底」时留白是**逐边取色**填的（上/下/左/右各用自己的边缘色），
  不会再出现「人像底部深色衣服、两侧浅背景，混出一条突兀色带」的情况
- 参数**记住在你的浏览器里**，下次打开还是上次调过的值
- 管理员可在「系统维护 → 证件照初始化参数」里设定**全校默认值**（即初始值），
  用户在页面上调的是自己的一份，互不影响
- **排版方式**：等比缩放居中（contain），**不会裁掉头部**
- **不换底**：跳过抠图、不联网，只按所选尺寸排版，适合背景本来就合格的白底照片
- 所有登录用户都能用；处理过程只在内存里完成，**照片不落盘、不写库**

## 十一、配置邮件 / 短信网关（可选）

未配置时验证码走演示模式（只输出到服务端控制台，不会真的发出去）。
如需真实发送，用管理员登录后在 **系统维护 → 邮件 / 短信网关** 卡片里填写并保存即可，
**无需重启**，也无需手工编辑配置文件。

### 11.1 邮件（SMTP）

| 项 | 说明 |
| --- | --- |
| 服务器 / 端口 | 如 `smtp.qq.com`、465（SSL）或 587（STARTTLS） |
| 账号 / 授权码 | 邮箱服务商提供的 SMTP 授权码，不是邮箱登录密码 |
| 发件人 | 留空则与账号相同 |

### 11.2 短信

支持两种服务商，在「服务商」下拉中选择：

| 服务商 | 密钥填写方式 | 其他必填 |
| --- | --- | --- |
| **阿里云短信** | `AccessKeyId:AccessKeySecret`（用英文冒号连接） | 短信签名、模板 CODE |
| **通用 HTTP 网关** | 网关约定的密钥，以 `Authorization: Bearer <密钥>` 发送 | 网关地址（http/https） |

通用网关收到的请求体为
`{"phone":"139****","code":"123456","text":"...","sign":"...","template":"..."}`，
自建网关按此约定接收即可。

### 11.3 常见问题

- **界面显示「未启用（演示模式）」**：表示必填项还没填全。阿里云要求密钥含冒号且签名、模板齐全；
  通用网关要求地址与密钥齐全。缺任一项都不会发送，也不会谎报「已发送」。
- **配置正确但仍收不到**：多为网关侧模板未审核、签名未报备或手机号在测试白名单之外；
  服务端控制台会打印网关返回的原始错误。
- 只配邮件则手机验证码仍走演示模式，反之亦然。
- 验证码有效期、重发间隔、单日上限在 `data\settings.json` 中调整
  （`code_ttl_seconds` / `code_resend_seconds` / `code_daily_limit`）。

> 安全说明：保存后再次打开配置页，密钥只显示掩码 `******`，不会回显明文；
> 如需更换请输入新值，如需删除请点「清除已保存的短信密钥」。

## 十二、AI 智能助手

**入口**：左侧菜单「AI 智能助手」（所有已登录账号可用）

本系统内置 AI 能力，**零配置即可使用**；管理员也可按需接入外部大模型增强。

### 12.1 智能分析（需「数据分析」权限）

按考试批次 / 考试类型筛选后点「开始分析」，输出：

| 输出 | 说明 |
|---|---|
| 数据概览 | 报名总数、待审核、通过 / 驳回 / 退回、通过率、覆盖批次数 |
| 分析结论 | 一段自然语言结论，可直接贴进工作汇报 |
| 处置建议 | 按紧急度排序的可执行建议，并带「去审核」等直达按钮 |
| 数据体检 | 11 类检查，异常项可展开查看涉及的考生（证件号脱敏） |
| 审核瓶颈 | 各批次待审量与已等待时长、平均审核耗时、审核员工作量、临近截止批次 |
| 报名趋势 | 近 14 天报名量曲线 |

体检覆盖：同批次证件号重复、同证件号姓名不一致、证件号不合法、手机号 / 邮箱 / 邮编格式异常、
必填项缺失、未上传证件照、审核积压（超过 72 小时）、班级为空、性别与证件号不符。

> AI 只能看到你本来就有权限看到的数据（全校 / 本院系 / 本年级 / 本班级），不会越权取数。

### 12.2 AI 客服（所有登录用户）

直接输入问题即可，例如：

- 用法类：怎么报名？审核状态都代表什么？批量导入的模板在哪里下载？怎么导出汇总表？
- 数据类：我的报名状态是什么？现在有多少条待审核？帮我看看数据有什么异常？
- 权限类：我的权限和数据范围是什么？

涉及实时数据的回答会先做权限校验：没有对应权限时会明确说明原因，而不是返回看不到的数据。

**直达深链**：`#/ai?tab=chat` 进入客服，`#/ai?tab=config` 进入大模型配置（仅管理员可点）。

### 12.3 接入外部大模型（可选，仅管理员）

**入口**：AI 智能助手 →「大模型配置」

| 配置项 | 说明 |
|---|---|
| 启用大模型 | 关闭时完全不联网，只用本地规则引擎 |
| 服务地址 | OpenAI 兼容地址，如 `https://api.openai.com/v1` |
| 密钥 | 只保存在本机 `data\settings.json`；接口只回「是否已配置」，不回明文 |
| 模型名称 | 如 `gpt-4o-mini`、`qwen-plus` |
| 超时 | 5-120 秒，默认 30 |
| 附加提示词 | 可选，追加到系统提示词 |
| **网络代理** | 访问境外模型用：填本机代理地址（Clash / V2Ray 一般是 `http://127.0.0.1:7890`）；<br>留空 = 跟随系统环境变量；填 `none` = 强制直连、忽略系统代理 |

启用后：智能分析会附加大模型的自然语言解读，客服遇到知识库未覆盖的问题由大模型兜底。
**未配置、超时或调用失败一律自动回退到本地结果**，不会影响软件本身的任何功能。

填写完可点「测试连接」验证；不再使用时可点「清除已保存的密钥」。

若模型部署在本机（如 Ollama、vLLM、LM Studio，地址形如 `http://127.0.0.1:11434/v1`），
系统**始终直连**——代理访问不到本机的服务，所以这类地址不受「网络代理」设置影响。

**接入境外模型（OpenAI / Claude / Gemini 中转）时填「网络代理」即可**，判定顺序如下：

| 目标地址 | 处理方式 |
|---|---|
| 本机（`127.*` / `localhost`） | 始终直连，忽略任何代理设置 |
| 外网 + 填了代理地址 | 走填写的代理 |
| 外网 + 填 `none` | 强制直连，忽略系统代理 |
| 外网 + 留空 | 跟随系统环境变量（HTTP_PROXY / HTTPS_PROXY） |

点「测试连接」时提示里会带上实际使用的代理，便于排查「配了代理却连不上」的情况。
注意：只支持 `http://` 与 `https://` 代理，不支持 socks5。

### 12.4 服务商预设与连接诊断

「大模型配置」页的「服务商」下拉内置 10 个常用厂商（OpenAI、DeepSeek、豆包、通义千问、
智谱、Moonshot、硅基流动、百川、本地 Ollama、自定义），选中后自动带出服务地址与候选模型名，
模型名也可手动输入。

**服务商以填写的服务地址为准自动反查**：改了地址就会重新判定，不会因为之前选过别的厂商而误判。
本地地址（`127.*` / `localhost`）永远直连；境外厂商未配代理时会明确提示需要代理。

点「测试连接」时**不改已保存的配置也能测**，结果按类型给出可操作的提示：

| 提示类型 | 典型文案 |
|---|---|
| 参数自检 | 「未填写服务地址」「服务地址多带了接口路径」「密钥为空」「超时需在 5-120 秒」 |
| HTTP 401 | 密钥无效或已失效（附厂商返回的原文） |
| HTTP 404 | 地址或模型不存在；本机模型未下载时提示先用 `ollama list` 查看 |
| HTTP 429 | 被限流或额度不足 |
| 网络异常 | 无法解析域名 / 连接被拒绝 / 超时 / 证书错误 / 代理不可用 |

**入口**：左侧菜单「实名认证」（考生自助提交，管理员审核）

### 13.1 考生自助实名

进入「实名认证」页填写**姓名 + 证件类型 + 证件号码**提交：

- 证件类型：居民身份证、中国港澳台居民居住证（香港 / 澳门 / 台湾）
- 提交后状态为「待审核」，管理员审核通过后变为「已通过」
- 一个账号只保留一条实名记录，重新提交会覆盖上一条并回到「待审核」
- 列表与详情里证件号一律**脱敏显示**（保留前 4 后 2）

### 13.2 第三方认证通道（预留）

系统预留了**支付宝**与**微信**两条官方实名通道，配置入口在管理员的「实名设置」里。

- 未配置密钥时点通道按钮会走**模拟流程**并明确标注「演示」，不会产生真实认证结果
- 配置齐全后才跳转官方授权页；**回调未通过时绝不会伪造成「已通过」**

### 13.3 管理员：审核与开关

| 开关 | 说明 |
|---|---|
| 启用实名认证 | 总开关，关闭后不显示实名入口、不做任何实名校验 |
| 允许本人自填 | 关闭后只能走第三方通道；若此时没有任何通道可用，保存会被拒绝 |
| 实名通过才可报名 | 开启后未通过实名的账号提交报名时会被拦下并提示 |

审核操作：在「实名认证」页的待审列表里通过 / 驳回（可填意见），已通过的也可以撤销。
**用户与权限管理**页的列表里有「实名」列，并提供「实名审核」入口（带待审数量角标）。

实名有两个实际作用：

1. **找回密码的核验依据**：核验通过实名记录的证件号，其次才是账号上登记的证件号
2. **报名门禁**：开启「实名通过才可报名」后，未实名账号无法提交报名

## 十四、系统维护与数据清理

**入口**：左侧菜单「系统维护」（仅管理员）

**运行信息**：版本、运行模式（正式 / 演示）、数据库路径与大小、导出目录与文件数
**数据规模**：账号数（含管理员 / 考生分项）、考试批次、报名数据、审核记录、导入批次

**局域网访问**：开关控制「是否允许局域网内其它电脑用浏览器打开本系统」，
**默认开启**。关闭后只监听 `127.0.0.1`，其它电脑一律访问不到。
页面会回显当前监听地址与所有可用网址；同事用带 IP 的地址访问即可。
**修改并保存后需重启程序才生效**（详见 1.1 节）。

**注册验证方式**：图形验证码 / 手机验证码（短信）/ 邮箱验证码，三个开关。
**至少保留一种**（全关会被拒绝），关掉的方式在注册页不会显示，
即便手工调用发码接口也会被拒绝 —— 不会谎报「已发送」。
手机号只走短信、邮箱只走邮箱。网关没配置时会给出提示，
但**找回密码不受这组开关限制**，否则关掉短信后所有人都找不回密码。

**证件照初始化参数**：设定全校默认的抠图阈值 / 边缘羽化 / 底部补底 / 留白填充，
以及可选的远程抠图接口地址。这里改的是「初始值」，
考生自己在「证件照制作」页上调的只影响他自己（见 8.5）。

**测试模式（模拟数据）**：

- **仅管理员可用**，开启后按设定条数（默认 5000）批量生成模拟报名数据用于压测，
  **只保证数量、不保证字段完整**
- 模拟账号统一 `mock_` 前缀，页面显示当前已有多少条
- **关闭即清空全部模拟数据**，正式环境不会留下测试数据
- 正式环境中请不要开启

**数据清理**（危险操作，清理后不可恢复）：

| 清理范围 | 效果 |
|---|---|
| 报名数据 | 清空两张报名表 + 审核记录 + 导入批次与失败明细（保留账号与批次） |
| 账号 | 清空所有账号，**仅保留当前登录的管理员** |
| 考试批次 | 清空所有批次（连带报名数据） |
| 导出文件 | 删除 `data\exports\` 下所有 xlsx |
| 全部（恢复出厂） | 上述全部执行 |

操作步骤：勾选范围 → 在确认框输入 **`确认清空`** → 点「立即清理」→ 二次确认。

> 执行前请先在「汇总导出」中导出需要保留的数据，或手动备份 `data\app.db`。

## 十五、常见问题

**Q：报名时提示「该批次当前不在报名开放期」？**
A：该批次报名窗口已截止或尚未开始，请联系管理员调整报名时间。

**Q：提示「您已报名该考试批次，不可重复报名」？**
A：同一考生在同一批次只能有一条报名记录；如需重新填写，请先在「我的报名」中撤回。

**Q：导出的 Excel 能否直接用于官方系统导入？**
A：可以。导出的表头与 Sheet 结构与官方模板逐字一致：
- 计算机类 → `Sheet1`(13 列表头) + `填表说明` + `sheet3`(机构/科目字典)
- 普通话 → `Sheet1`(20 列表头) + `Sheet2`(职业字典) + `Sheet3`(省市区) + `Sheet4`(模板版本)

**Q：数据量很大（1 万条以上）导出会不会卡死？**
A：不会。超过 3000 行时系统自动切换**流式写入**（游标分批取数 + openpyxl write_only），
内存占用与行数基本无关。实测 12000 行端到端导出约 1.2 秒。

**Q：数据存放在哪里？如何备份？**
A：全部数据在 exe 同级的 `data\app.db`（SQLite 单文件）。直接复制该文件即可备份；
导出过的 Excel 在 `data\exports\`。

**Q：想清空数据重新开始？**
A：关闭程序后删除 `data\` 目录，重新启动会重建数据库（**只创建一个管理员账号**）。
也可在「系统维护 → 数据清理」中选择要清理的范围。

**Q：图形验证码看不清？**
A：点击验证码图片即可刷新。

**Q：收不到邮箱 / 手机验证码？**
A：说明尚未配置网关，此时验证码会输出在 exe 的控制台窗口中（演示模式），
请查看窗口中的 `[验证码] ... 验证码=123456` 行。配置方法见第十一节。

**Q：账号被禁用了怎么办？**
A：联系管理员在「用户与权限管理」中把该账号的开关重新打开。

**Q：班主任 / 二级学院审核登录后看不到任何数据？**
A：说明该账号未绑定班级 / 院系。请联系管理员在「用户与权限管理」中补全，
或让管理员用「权限组核验」查看所有异常账号。

**Q：为什么想给某个账号设「全校」范围却保存不了？**
A：数据范围只能**收窄不能放宽**。角色的默认范围就是该账号的上限：
班主任最高「本班级」、二级学院审核最高「本院系」。需要更大的范围请改用审核员 / 管理员角色。

**Q：「本年级」范围和预期不一致？**
A：报名表没有年级列，本年级是按考生账号上的年级字段关联班级匹配的。请确认批量导入时
表里有「年级」列（或指定了整批默认年级），并且勾选了「同时创建考生账号」——
否则导入生没有年级信息，这一档会漏掉他们，请改用本院系 / 本班级。
